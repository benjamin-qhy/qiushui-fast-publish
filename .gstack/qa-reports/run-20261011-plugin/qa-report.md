# MultiPost 开发版浏览器测试

日期：2026-10-11
范围：Chrome 中已由用户安装的开发版插件。仅检查加载、界面入口、网页联动及提交前的交互，不发布内容，不修改产品代码。
工具：Codex CUA。依照主机工具要求使用 CUA，无法使用 Aside 或其他技术控制浏览器。

## Charters

1. 确认已安装插件的可观察入口。预期可访问插件界面；浏览器内置页面不受控制是工具限制，不记为插件缺陷。
2. 查找官网的网页联动入口。预期可观察插件识别或进入插件功能；只操作本次创建的官网标签。
3. 若入口可达，检查主要页面和输入交互，停在提交前。无法访问入口时将该项标记为阻塞。

## Results

结论：尚不能确认开发版插件正常使用。已完成官网提交前流程检查，但未取得开发版插件被调用的证据。

- 官网 https://multipost.app/ 可打开。空内容点击“选择发布平台”后出现“内容不能为空”。
- 填入合成测试文本后点击“选择发布平台”，显示国内和国际平台选择页，并显示自动发布关闭。没有点击“发布到所有平台”。
- 返回“填写内容”后测试文本仍在。随后清空本次测试文本并关闭本次创建的标签页。
- CUA 捕获的 error/warn 日志返回空数组；仅限本次页面捕获，不能证明插件后台无错误。
- 无插件界面、账户刷新、网页填充、上传或实际发布验证。浏览器控制工具无法操作工具栏插件图标和 Chrome 内置扩展管理页；因此未验证所装扩展的 ID、版本和后台状态。
- manifest 的 externally_connectable 仅列出 paiban.md 和 localhost:2663，但存在全页面 content script，且后台初始化信任 multipost.app。不能据此判断官网联动失效。
