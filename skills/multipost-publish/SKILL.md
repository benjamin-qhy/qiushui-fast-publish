# FastPublish 本机发布

通过本机 CLI/API 把内容目录交给 FastPublish 扩展，返回逐平台有证据的结果。Agent 只需文件读写与命令／HTTP 调用能力；发布页面的打开、素材上传、填写和结果核对均由扩展执行。运行时不依赖 ChatGPT/Codex 桌面应用的浏览器或电脑控制权限；这些工具仅供当前开发人员排查和验收，不属于本 Skill 的运行步骤。

本期处理 `DYNAMIC` 图文和纯文字。带图片时已在真实会话核对：小红书、微信视频号、抖音、今日头条、即刻、知识星球、脉脉和 X 的 `prepare` 为 `filled`；微信公众号的 `save_draft` 为 `draft_saved`。无图片时，配置中的 `textVerified` 只包含已由本机插件真实核对无图填写的今日头条、即刻、知识星球、脉脉和 X；其他四站自动跳过并说明原因。知识星球的目标星球在平台配置的 `targets` 中指定。以前的公众号文章草稿与视频号视频适配保留在代码中，但不在本期默认平台配置中。图文公开发布已在本机验证小红书、抖音、即刻、知识星球、脉脉和 X；今日头条曾提交进入审核，不能算公开成功；微信公众号和微信视频号未完成公开发布验证。公众号当前只能确认图文草稿，不能把它当作群发。视频号动态图文现配置为直接发表；发表后的平台作品回执仍需真实验证，不能仅凭点击记为成功。

脚本以自身路径定位项目，命令中的 `<skill>` 是本文件所在目录。读取 [内容目录规范](references/content.md) 来构造或校验输入。

1. 执行 `python3 <skill>/scripts/multipost.py plan-config <内容目录>`，逐个平台预检默认配置及其目标动作。默认配置是 `<skill>/config/platforms.yaml`，可显式指定 `--config`；`--platforms` 只能缩小到已配置平台的子集。无图内容自动取 `textVerified` 与配置平台的交集，输出计划和跳过原因；没有合格目标则停止。预检失败时先修正材料。单个平台可使用 `plan <目录> --platforms <平台键> --action <动作>`。
2. 执行 `python3 <skill>/scripts/multipost.py connection`，确认插件已配对并在线。若本机服务未启动，在可持续运行的终端执行 `python3 <skill>/scripts/multipost.py serve`。未配对时报告需要安装配置，见[一次性安装与移植](references/setup.md)；浏览器未运行时提示用户打开已配对浏览器并等待下一次心跳。
3. 执行 `python3 <skill>/scripts/multipost.py run-config <内容目录>`。命令按配置顺序逐个平台提交、等待结果并输出独立任务 ID；配置为 `publish` 的视频号先创建 `prepare` 任务，核对为 `filled` 后才在同一标签页创建关联的 `publish` 任务。插件在后台领取任务，无需 Agent 打开、点击或读取浏览器页面。单个平台使用 `run <目录> --platforms <平台键> --action <动作>`。插件最长约 30 秒轮询一次。
4. 以扩展回执为执行结果。有图内容的 `filled` 需要字段与图片证据匹配；无图内容的 `filled` 需要正文匹配且图片数为零。公众号 `draft_saved` 且返回平台草稿 ID、编辑页地址已核对时报告“草稿已确认”；同一内容已有该草稿回执时不重复创建。视频号 `publish` 要分别报告准备任务 ID 和发表任务 ID；发表点击后没有平台作品证据时报告“结果不确定”，不能称为“发布已确认”。其余平台以实际回执报告“已填写”。超时或中间状态不报告完成，保留任务 ID，用 `status <taskId>` 查询。
5. 需登录／验证码／补填信息时，明确提示用户在插件保留的平台页面处理。小红书可在安全场景继续原任务；视频号动态图文只有在上传入口／登录问题发生于上传前时才允许 `resume <taskId>`。若头条或知识星球的编辑器里有先前由本 Skill 填写的内容，先用原任务 `resume <taskId>` 只读核对；在确认来源任务确实为同平台 `filled`、目标相同且图片文件逐一相同后，可对原任务使用 `resume <taskId> --replace-from <来源任务ID>`。扩展再次核对页面旧正文和图片数量后才替换；知识星球旧图片已消失时会补传。其余已有内容不覆盖。公众号草稿创建可能产生平台记录，视频号视频可能已经上传，这两类任务当前不自动恢复；先核查原任务和页面，防止重复创建或上传。结果不确定时不重新提交内容目录。

用户明确授权公开发布具体内容和目标平台后，对 `filled` 的原任务使用 `publish <原任务ID>`；它创建关联的发布任务并复用原页面，发布前再次核对正文、标题和图片数。它不能用于公众号图文草稿群发。发布任务返回 `published` 且有作品链接／ID时才关闭本次任务页；知识星球可通过唯一匹配的动态流内容和三张图片确认已发布，但若无单帖链接则保留页面。`submitted_pending_review` 是待审核，`result_unconfirmed` 是未知，均保留页面。发布点击发生后禁止再次执行 `publish` 或重交内容；对未知结果仅使用 `reconcile <发布任务ID>` 做只读核对。`publish-resume` 只适用于扩展明确记录为点击前暂停的安全状态，不能用来重试结果未知的任务。逐平台返回任务 ID、实际状态、作品链接或可核对证据及未完成原因。

回执默认保存在项目忽略目录 `.multipost-local/tasks/`，扩展同时保存原任务与标签页引用。Skill 移植到其他位置时，通过 `MULTIPOST_STATE_DIR` 指向已运行服务的同一个私有状态目录。返回任务 ID、平台、实际状态、插件核对证据和下一步；`queued`、`claimed`、`running` 均是中间阶段。

标签目前作为文本附在正文；原生话题选择尚未验证，报告时单独说明。公众号动态草稿会产生持久记录并保留平台 ID；视频号动态图文经用户授权后按配置在字段和媒体复核通过时点击“发表”。默认平台配置中的 `actions` 明确指定逐平台目标动作，不应把“已填写”“草稿已确认”和“发布已确认”互换。公开发布须使用用户认可的内容包，并以平台回执判断实际结果。

无图片时只把正文与独立 `tags` 转成的 `#标签` 文本送入编辑器；独立 `title` 不发送。旧编辑器若有不同内容，停止并保留原任务；仅在严格核对为本 Skill 以前填写的已知内容时才允许显式恢复。`filled` 不保证刷新页面后持久保存。
