# 发布账号选择

每次发布（包括图文、纯文字、文章和视频）先读取项目 `00-约定/发布规范.md` 的“发布账号配置”节。配置由该项目维护，不写入通用 Skill 默认值。

## 解析与覆盖

发布规范使用自然中文、列表或表格，由 Agent 理解；不要求用户维护 JSON、固定字段名或固定标题。先完整阅读发布规范和本次指令，提取默认账号、实际名称、明确配置的别名及各平台绑定。只从文档、用户本次明确指令或当前会话核实结果取值，缺失信息保持未知，不猜测另一个账号的平台、别名、账号 ID 或浏览器。

例如用户可写：“默认使用我叫秋水，别名是秋水、主号。另一个账号叫秋水AI咖啡馆，暂未配置别名。这次指定其他账号时只影响本次。”

Agent 将中文规则转换为内部参数，通过标准输入交给解析命令校验，无需在业务目录创建额外 JSON 文件：

```sh
bun <skill>/scripts/multipost.ts resolve-account --input - --platforms 小红书,抖音
bun <skill>/scripts/multipost.ts resolve-account --input - --platforms 小红书 --account 主号
```

标准输入为程序内部 JSON：defaultAccount 是默认账号名称，accounts 是账号数组。每项包含稳定的配置 id、实际名称 name、别名数组 aliases 和按中文平台名索引的 platforms；平台绑定包含 nickname、accountId、browser、profile。未核实的字段用 null，未确定的平台不生成映射。browser 为 chrome 或 edge，profile 为浏览器个人资料名称。这些字段只用于程序校验，不要求写回发布规范。旧版文档 JSON 输入仍兼容。

实际名称及别名精确匹配（忽略首尾空白）；不做模糊猜测。优先使用本次明确账号，其次使用规范中的默认账号。每个账号可以关联多个平台，各平台实际昵称可以不同。解析命令只读，无论成功或失败均不修改默认账号。

名称或别名跨账号冲突时停止，列明冲突并请用户选定账号、确定唯一名称后修正；不优先选择默认账号。未知名称、平台缺少映射或字段未核实均停止该平台执行，报告需要补充项。resolved 仅表示配置完整，不表示身份已核实。

用户明确说“以后默认用……”时，先唯一解析目标，再仅修改中文规范中的默认账号；“这次用……”只覆盖本次参数，不修改文档。账号名称、别名和各平台绑定仅在用户要求或实际核实后更新。不记录凭证、配对令牌或 cookie。

## 执行环境与身份

1. 根据解析出的 browser/profile 确定执行环境。当前单服务只配对一个执行器；connection 只返回插件 ID 与在线状态，不能识别 Chrome/Edge 或个人资料，也不能证明账号正确。已有配对无法与目标环境对应时，请用户在指定浏览器个人资料中重新配对后继续。不得按当前前台浏览器猜测，也不得把另一个浏览器当作回退。
2. 上传前调用 `account --platform <平台键>`，读取当前会话并对比配置的稳定 ID。该入口现支持 VIDEO_WEIXINCHANNEL、VIDEO_REDNOTE、VIDEO_DOUYIN、DYNAMIC_REDNOTE。其他类型/平台尚不能用此接口核实时，停止并说明需要该平台的实时身份核对能力；不把昵称或旧缓存当作 ID 证据。
3. 账号不一致或无法读取时，停止该平台，提示在指定环境切换正确账号，再重新核对。多平台可继续执行已核对成功的平台；遇到需要重新配对的另一环境，先等当前任务结束再切换，不在运行中更换执行器。
4. 视频任务的账号名称写入平台实际 nickname，账号ID写入已配置且实时核对一致的 accountId；小红书图文使用 expectedAccountId。视频执行器在传入 expectedAccountId 时会在上传/发表 handler 前再次读取并核对，失败返回 needs_attention。

当前未实现按别名自动调度多个浏览器、自动登录或自动切换个人资料。切换配对后，只重新处理尚未上传的账号核对失败任务；已经点击发表或结果未知的任务先查原回执，不因切换账号重复提交。
