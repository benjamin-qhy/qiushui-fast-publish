# 明确视频任务接口

本文由FastPublish仓库维护，项目侧同步部署。工具校验调用者明确提供的字段，不读取项目默认规则、不解析发布文案、不推断账号，也不限定项目目录布局或素材名称。

## 生成快照

```sh
bun <skill>/scripts/multipost.ts generate-video-task <作品绝对路径> --input - --source-root <来源根目录>
```

`--input -`从标准输入接收JSON，也可指定参数文件路径。Agent可直接传入参数，不必在业务目录额外创建参数文件。`--source-root`默认作品目录，仅决定来源文件相对路径的解析位置。视频和封面始终限制在作品目录内。

输入示例，字段均由调用者决定：

```json
{
  "作品": "作品名称",
  "时区": "Asia/Shanghai",
  "视频文件": "视频.mp4",
  "来源文件": ["作品/发布文案.md", "发布规范.md"],
  "本次覆盖": [],
  "平台任务": [
    {
      "平台": "视频号",
      "账号": {"名称": "目标账号名称", "账号ID": null},
      "封面": {"竖版": "封面-竖版.png", "横版": null},
      "标题": "明确标题",
      "描述": "明确描述",
      "话题": [],
      "合集": null,
      "定时发表": false,
      "定时发表时间": null,
      "声明原创": true,
      "目标动作": "填完保持不动",
      "待补充": []
    }
  ]
}
```

必需字段缺失时拒绝生成，不自动填默认值；null、空内容或待补充仍会阻塞执行。合集null且没有相关待补充项表示调用者已明确不加入合集。支持视频号、小红书、抖音，平台列表为本次选定范围。

输出为作品根的发布任务.json，格式版本1.1，增加来源根目录、来源/媒体SHA256、批次ID、生成时间和材料状态。生成成功不代表平台支持或预检通过。相同明确输入保持批次；文件变化生成新批次。旧1.0格式需由调用者重新整理参数后生成，不自动读取旧规则补齐。来源根目录位置变化时也须重新生成。

## 预检与执行

```sh
bun <skill>/scripts/multipost.ts plan-video-task <作品目录> --platforms 视频号
bun <skill>/scripts/multipost.ts run-video-task <作品目录> --platforms 视频号 --timeout 900
```

新协议仅由上述显式入口启用，底层/submit使用inputFormat=publication；旧plan/run/plan-config/run-config继续读取content.json/content.yaml，不因中文文件存在而切换。可用中文平台名称或VIDEO平台键缩小范围，不增加平台。

执行直接调用上游三个视频handler。填完保持不动对应isAutoPublish=false；直接发布对应true；旧“存草稿”映射为填写后停留，不调用保存按钮。不再要求额外--allow-publish参数；Agent依据用户请求选择目标动作。

账号ID可为空，不作为执行拦截。来源与媒体SHA256保留为记录，不做页面一致性或来源变化拦截。定时时间转换为时间戳后传给上游。合集仍无上游参数，非空时应说明不支持。

同批次同平台使用upstream-v1命名空间，隔离旧检查流程的失败任务。回执executed表示handler已返回，不等于平台确认发布。各平台独立执行并报告结果。

服务使用普通serve模式；历史--draft-only启动参数仍会拒绝自动发表，切换模式需重启服务。升级须加载videoTaskRevision>=46扩展并重启服务，保留原私有状态及配对。
